# <run> — inventory

Everything actionable from `findings.md`, in one place, so `plan.md` and `handoff.md` can point
here rather than carrying it. Delete this paragraph when copying.

**Nothing here is agreed work.** `plan.md` §1's rule stands: everything agreed to be built is
scheduled there and nowhere else. This is the **input** to the `plan.md` item that works through
this run.

**Sections are by where an item goes next**, which is the one axis that does not leak. An item is
often a fix and a change and an addition at once, so what it *is* cannot file it; what happens to
it next can.

**The inventory says what to do. `findings.md` says why we believe it.** Evidence stays in the
finding, and every row here names its finding rather than repeating it.

**A citation between two records of one run resolves both ways.** A candidate names its evidence,
and the finding names the candidates it produced, under `**Acted on:**`. This side is the source
of truth and the other is generated by `check_docs.py --fix`, because a rule needing two hand
edits per link gets half-done. A citation to anything outside the run — `docs/`, a source file, a
build log — stays one-way, because nothing there can name us back.

**A finding that produced no candidate is reported.** It is either work nobody filed, or a finding
already closed elsewhere, and both are worth seeing. It is never stamped `nothing`: two of dogfood
#4's were fixed at the full-test pass before the inventory existed, and writing `nothing` would
have put a false statement in the record.

**This run's queue item is done when no candidate is still `open`** — each is scheduled, built, or
declined with a reason. Otherwise this file becomes the next place things collect dust.

## 3. Candidates

One flat table. **The id never changes and is never reused**, so an item can be re-tagged without
renumbering and another document can cite it.

- **Kind** is `fix`, `change`, `add`, `absorb` or `decide`. A tag, not a section.
- **Size** is `cheap` for an afternoon, `item` for a scheduled build with a log, `sitting` for
  something that needs deciding before it can be sized.
- **Status** names where it went, and the vocabulary is `plan.md`'s sections: `open`,
  `accepted §2.1`, `deferred §2.2`, `scheduled P3-n`, `built <build log>`, `declined: <reason>`.
  Most candidates never become a `plan.md` row; `accepted` and `deferred` are what stop §1 from
  swelling to hold a whole run's output.
- **Blocked by** names other ids in this table, or is empty.

**The table is in the order to take them, and the top row is what the sitting does next.** Priority
is a judgement and it changes; two invariants under it are not, and `check_docs.py` holds both:

- **A live blocker appears above everything it blocks.** Otherwise a sitting reading top-down hits
  work it cannot start.
- **Resolved rows sit below every open one**, so the working set is the top of the table.

**When a blocker resolves, clear it from the rows it blocked.** `Blocked by` names what blocks the
candidate now, not what once did. A stale blocker is reported.

Reordering is free because the id never moves, which is the point of separating identity from
position.

A candidate that needs argument gets a detail block below the table. One that does not is a row,
and its evidence is in the finding.
